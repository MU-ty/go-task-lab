# 从 Go 语法到独立交付后端

学习目标是：能够从空目录创建一个多用户 JSON API，持久化数据、保护用户资源、编写测试，并在容器/服务器中运行与排错。课程是否完成，以交付结果和解释能力验收，不能由阅读章数保证。

## 六个阶段

| 网站章节 | 能力 | 阶段交付 |
| --- | --- | --- |
| 01–10 | 语法、数据类型、接口、并发入口 | 写出并解释一个独立 Go 程序 |
| 11–20 | 闭包、资源清理、错误、JSON、泛型、同步、测试 | 处理错误和边界，写表驱动子测试 |
| 21–28 | 模块、HTTP、路由、严格 JSON、CRUD、middleware、取消、客户端 | 可在本机监听端口的 API 与 HTTP 测试 |
| 29–33 | 仓储接口、PostgreSQL、迁移、事务、分页 | 数据重启不丢失，失败事务无部分写入 |
| 34–38 | 会话、授权、密码、同源、输入与资源预算 | 两用户隔离，撤销会话和安全失败测试 |
| 39–44 | 日志、集成测试、CI、探针、关闭、Docker | 有运行手册和故障演练的可交付服务 |

网站每个后端章节都有「05 后端实战」：目标、步骤、参考源码和验收条件。第 44 章串起全部阶段。浏览器示例利用 Go WebAssembly 与 httptest 在进程内运行；它们不是已经部署的公网后端。数据库、真实端口和容器练习在本机完成，OneCompiler 用于修改独立代码。网站不保存你的服务凭据。

## 从空目录做一次

1. 写需求和 HTTP 合同：注册、登录、退出；任务创建、查询、分页、完成/取消完成和删除。明确 400/401/404/409/413/415/429 的含义。
2. `go mod init` 建立模块，只写 healthz 与 ServeMux。用 curl 和 httptest 验证头、状态和错误方法。
3. 增加严格 JSON 与输入校验，再建立小 Store 接口。先写带锁内存仓储，完成 CRUD 的成功和失败测试。
4. 创建 users、sessions、tasks 与 audit_events 的迁移。接 PostgreSQL，所有用户输入用参数；SQL 仓储保持 HTTP 合同一致。
5. 创建任务时同时插入审计。使第二次写入失败，验证事务回滚，而不是仅验证成功 Commit。
6. 注册使用 Argon2id，登录生成 32 字节随机会话，数据库存 token 摘要与到期时间。身份写入请求上下文，每条任务查询都带 owner_id。
7. 加入两用户越权测试、注销失效、分页上限、输入大小与认证预算。确认错误请求不会修改状态，也不在日志中泄露凭据。
8. 配置 Server 超时、结构化日志、healthz/readyz、信号关闭与定期过期会话清理。对故障和退出做实测。
9. 用 Docker 构建非 root 镜像，执行迁移后启动 API，重启并验证持久化。生产 TLS/秘密/代理策略另行配置，不能把开发配置直接公开。
10. 让另一个人只凭 README 启动并完成请求链，再对照 [参考项目](../examples/task-api/README.md) 改善可读性与验证。

## 最终验收清单

- 能在全新环境下载依赖、测试、构建、迁移并启动。
- 能解释 Handler、Middleware、Context、Store、连接池、事务与会话各自职责。
- 注册不保存明文密码；同一密码两次哈希不同，验证均成功；错误密码安全失败。
- 无效、过期或撤销会话返回 401，认证头与密码不出现在日志中。
- A 的任务不能被 B 列出、读取、更新或删除；伪造 owner_id 被拒绝。
- JSON 未知字段、多段正文、超长标题、非法 ID、分页边界与超大 Body 有明确状态码。
- done=false 可以显式更新；删除成功没有正文；新建任务给出 Location。
- SQL 带单引号的标题仍是普通数据；数据库约束在并发或绕过 HTTP 时仍有效。
- 审计写入失败后，任务写入也被回滚；所有事务操作通过 tx 执行。
- 重开数据库连接、重启 API 后任务仍存在；迁移重复执行不会重复建表。
- 数据库故障时 readyz 为 503，healthz 仍能说明进程存活；取消和查询超时有上界。
- 并发、HTTP 合同与真实 PostgreSQL 集成测试在 CI 通过，缺少数据库时的跳过不伪装为成功验证。
- 进程收到停止信号后有界退出，后台任务退出、数据库最后关闭。
- 容器非 root；本地数据库仅绑定回环地址；生产 HTTPS、配置和秘密与源码分开。
- 有数据库备份、恢复演练与应用回滚计划；能通过请求 ID 定位一条失败请求。

## 排错时先检查

| 现象 | 先检查 |
| --- | --- |
| 连接被拒绝 | 服务进程、监听地址、端口占用、容器状态 |
| 401 | Bearer 格式、token、到期时间、是否已经注销 |
| 404 | ID、路由，以及资源是否属于当前账号 |
| 409 | 邮箱是否已存在，数据库唯一约束 |
| 415/400 | Content-Type、字段名、单段 JSON 和参数边界 |
| 429 | 认证速率/并发预算，不要无限重试 |
| 数据重启丢失 | 是否仍用内存模式，DATABASE_URL 和持久卷 |
| 数据库表不存在 | 是否先执行 migrate，是否连接同一个库/schema |
| readyz 503 | 数据库连接与迁移状态，再查内部日志 |
| 请求退出不了 | Context 是否传到底层、channel 是否监听取消、关闭顺序 |

## 超出毕业项目之后

实际发布、HTTPS、备份恢复与回滚步骤见 [部署运行手册](DEPLOYMENT.md)。

掌握此基线后可继续：游标分页和幂等键、分布式缓存一致性、后台队列及重试/死信、指标与链路追踪、压力测试与性能剖析、灰度发布与高可用、密码重置/邮件验证、OpenAPI 客户端生成。优先从真实需求出发，每次扩展加入失败、恢复与验收测试；不需要先掌握微服务框架才能写可靠的单体后端。
